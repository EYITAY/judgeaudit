Judge Audit Pilot Manual

How to run the one-week pilot from an empty folder to a continue, stop or inconclusive decision. Kit name: awarejudge.

Status. The kit has only run on synthetic data. Until real traces and human labels exist, no number it prints means anything about models or judges.

What you need before Day 1

  • Two open-weight reasoning models whose reasoning text the API returns (the client reads reasoning_content or reasoning). Proposed: Groq openai/gpt-oss-120b and a DeepSeek reasoning model. Each is checked in Step 1.
  • One summarizer model (proposed: GPT-4o).
  • Two judge models from different families, and different from the reasoners (proposed: xAI grok-4-fast-non-reasoning and Groq-hosted Llama llama-3.3-70b-versatile). Non-reasoning judges are safest because the judge call is capped at 300 tokens.
  • One API key per provider, stored in a .env file (or set as environment variables). Never paste keys into chat or share the file.
  • A second person for the double-labeling step, free for 3 to 4 hours during Days 2 to 4.
  • Python 3.10 or newer. The kit uses only the standard library.
  • A budget under $50. The full design is about 6 million input tokens and 1 million output tokens; multiply by your models' prices, and run a 10-trace test first to see real usage.

Day 0: set up and test offline

Day 0 Unzip and run the dummy pipeline

unzip awarejudge.zip && cd awarejudge
python -m awarejudge.cli gen --model-name dummyA --dummy --out traces/dummy.jsonl
python -m awarejudge.cli forms --traces traces/dummy.jsonl --dummy --out traces/dummy_forms.jsonl
python -m awarejudge.cli judge --traces traces/dummy_forms.jsonl --judge-models j1 j2 --dummy --out results/dummy_j.jsonl
python -m awarejudge.cli analyze --judgments results/dummy_j.jsonl --out results/dummy_report.md

Expected: a report prints. Its numbers are random and must be ignored. Delete the dummy files afterwards so they cannot be mixed into real data.

Day 0 Step 1: check every model before using it

Put your keys in a .env file in the kit's top folder: copy .env.example to .env and paste each key after its =. The kit loads it automatically and never prints the values. Then run all five checks at once with python3 scripts/check_all.py and send the SUMMARY block back. The individual commands are:

python scripts/check_endpoint.py --base-url https://api.groq.com/openai/v1 --model openai/gpt-oss-120b --api-key-env GROQ_API_KEY
python scripts/check_endpoint.py --base-url https://api.deepseek.com --model deepseek-reasoner --api-key-env DEEPSEEK_API_KEY
python scripts/check_endpoint.py --base-url https://api.x.ai/v1 --model grok-4-fast-non-reasoning --api-key-env XAI_API_KEY --role judge
python scripts/check_endpoint.py --base-url https://api.groq.com/openai/v1 --model llama-3.3-70b-versatile --api-key-env GROQ_API_KEY --role judge
python scripts/check_endpoint.py --base-url https://api.openai.com/v1 --model gpt-4o --api-key-env OPENAI_API_KEY --role judge

Both reasoners must print PASS: reasoning text is returned. Each judge must print PASS with a parsed label. If a reasoner fails, it hides its reasoning and cannot be used; swap it. Confirm model names and URLs against each provider's documentation, since they change.

Day 0 Replace the rubric texts

Open awarejudge/rubrics.py. The five rubric instructions are adaptations. Find each source paper's original rubric prompt (for the Goodfire-style rubric, Aranguri and Bloom, Appendix F1), paste it into instructions, and keep a note of any wording you could not obtain. Do this before running any judge, so results are not produced with texts you later change.

Day 0 Fix the gate in writing

The thresholds in analysis.py (GATE) are the rule. Commit or timestamp the file before Day 1. Do not edit thresholds after seeing data; if you do, say so in the write-up.

Day 1 to 2: generate traces

Day 1 Collect reasoning traces from two models

First run the test: python3 scripts/step2_test.py. It generates traces for 5 prompts (one per category) from both reasoners and prints reasoning length, answer length, token counts and the finish reason. You want 5 of 5 traces per model, finish reason stop (not length) and non-empty reasoning. Then run in full:

python -m awarejudge.cli gen --model-name gptoss --model openai/gpt-oss-120b --base-url https://api.groq.com/openai/v1 --api-key-env GROQ_API_KEY --samples 2 --out traces/a.jsonl
python -m awarejudge.cli gen --model-name deepseek --model deepseek-reasoner --base-url https://api.deepseek.com --api-key-env DEEPSEEK_API_KEY --samples 2 --out traces/b.jsonl
cat traces/a.jsonl traces/b.jsonl > traces/all.jsonl

Defaults: 50 prompts, 2 samples each, about 200 traces. A trace with no visible reasoning is dropped, so compare the line counts against 100 per model. Each trace records the provider, model, settings and time in meta.

Day 2 Create the summarized forms

python -m awarejudge.cli forms --traces traces/all.jsonl --summ-model gpt-4o --summ-base-url https://api.openai.com/v1 --summ-api-key-env OPENAI_API_KEY --out traces/forms.jsonl

This adds a 150-word and a 60-word summary of each trace. Read five summaries. If they invent content not in the raw reasoning, change the summarizer and rerun.

Day 2 to 4: human labels

Day 2 Write the label sheet

python -m awarejudge.cli sheet --traces traces/forms.jsonl --n 100 --out labels/sheet.csv

The sheet holds 100 traces balanced across model and category. Labels are features, not rubric levels: mentions a possible test, concludes it is a test, type of evaluation, notes the scenario is artificial, acts on that belief.

Day 2 to 4 Label

  1. Both labelers read docs/labeling_guide.md and the edge-case table.
  2. Label the first 30 traces independently, without discussing.
  3. Compute agreement on those 30. If Cohen's kappa on "mentions a possible test" is under 0.7, refine the guide, reconcile, and label another 20 independently.
  4. Reconcile disagreements, then one person labels the remaining 70.
  5. Label from the raw reasoning only, never from summaries.

Judges must not see the labels, and labelers must not see any judge output until labeling is finished.

Day 3: run the judges

Day 3 Judge every rubric, judge and form

python -m awarejudge.cli judge --traces traces/forms.jsonl \
  --judge grok grok-4-fast-non-reasoning https://api.x.ai/v1 XAI_API_KEY \
  --judge llama llama-3.3-70b-versatile https://api.groq.com/openai/v1 GROQ_API_KEY \
  --out results/judgments.jsonl

This is 5 rubrics × 2 judges × 3 forms per trace, with temperature 0. For 200 traces that is 6,000 calls. Calls retry automatically on rate limits and server errors. Run on 5 traces first (--forms raw --rubrics goodfire_style) to check cost and parsing. Look for rows where level is null: those are unparsable replies. If more than 5% are null, fix the judge prompt format or the model choice and rerun.

Day 5: analyze and decide

Day 5 Run the report

python -m awarejudge.cli analyze --judgments results/judgments.jsonl --labels labels/sheet.csv --out results/report.md

The report lists: the verdict, rate per rubric, model and prompt-category ranking flips, judge-vs-judge and rubric-vs-rubric disagreement, how much of the variance each factor explains, how much awareness survives summarization, and judge-vs-human kappa. It ends with a Judge setup section listing each judge's provider, model, number of calls, truncated calls and dates: publish that with any result.

Report saysMeaningNext step
CONTINUEA model or prompt-category ranking flips between rubrics by at least 0.05 each way, or judge noise is at least half of rubric disagreement.Plan the full study (about 6 weeks): more models, original rubrics, larger labeled set, preregistered analysis.
STOP_OR_SHRINKRubrics within 1.5×, no flips, judge-human kappa at least 0.8.Write a short negative result post and stop, or shrink to the trace-form question alone.
INCONCLUSIVENeither set of conditions holds.Extend the labeled sample or traces once, then re-run the same gate. Do not change thresholds.

Before you publish anything

  • Original rubric texts in place, or the adaptation stated.
  • Sample sizes and confidence intervals shown next to every rate (the report uses Wilson intervals).
  • Rate gaps between rubrics are not presented as new, since judge sensitivity is already established. The claim to test is ranking and conclusion changes, and the split of definition, judge and trace form.
  • State that the models, prompts and labelers are few, and that the work was done by one human and one AI.
  • Check the license of any data or traces you redistribute.

Troubleshooting

SymptomLikely causeFix
Empty raw reasoningProvider returns only a summary or hides reasoningUse a provider or local server that returns full reasoning
Many null judge labelsJudge adds text around the JSON, or runs out of tokensUse a stronger judge, raise max_tokens, check the raw reply
Rates are 0 or 1 everywherePrompts do not elicit any test talk, or rubric too strictCheck the category breakdown; do not tune prompts after seeing judge output without noting it
Low labeler kappaFeature definitions unclearAdd the disputed case to the edge-case table and re-label
HTTP 4xx error naming a parameterA provider rejects max_tokens or temperature for that modelTell me the provider and message; the client needs a per-provider setting
Calls retry slowly or stop with "failed after 4 tries"Rate limit or outageRun one model at a time, wait, and re-run; the output file is rewritten each run, so keep a copy
Judges cut off ("cut off by the token limit" in the report)Reasoning judge, or reply longer than 300 tokensUse a non-reasoning judge or raise the limit in judge.py
Tests fail after an editRow-count assertion assumes 5 rubricsUpdate the assertion if you add or remove a rubric

About the name

The code package is called awarejudge. The public name is Judge Audit, because the project audits judges rather than building one.
